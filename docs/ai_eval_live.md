## What this does and does not prove

This is live model output. `minimax/minimax-m3:free` wrote every report scored above, and
the groundedness figure is therefore a measurement of a language model rather
than of our own renderers — the reports it got wrong are listed by name.

Read the score as one sample, not a constant. A language model is sampled, so
an identical re-run moves the number and changes *which* reports fail — ours
moved by a report between two consecutive runs. What does not move is the
direction of the guarantee: whatever the model invented on any given run, the
check caught it. Compare models on this figure only across several runs.

A score below 100% is the system working, not failing. The claim Loom makes is
not that a model never invents a number; it is that an invented number never
reaches an operator. Every ungrounded report above was caught by the same check
that runs in production, before the report was shown, and the check found them
without being told which ones to look at.

Run it against a different model and every number here is recomputed with no
change to this file. That is the point of the provider boundary: the model is an
input to the evaluation, not an assumption inside it.
