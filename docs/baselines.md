# Baselines — Loom against the alternatives

Generated by `python -m loom.baseline`. Every comparator sees the same sensor-filtered
event stream the twin saw, so the difference is the mechanism, not the data.

`threshold` = alarm when a measured cycle exceeds takt x 1.05, no persistence,
no inference. `detection` = active-period method (Roser) with the same persistence rule
Loom uses, so it is an alarm and not a continuous signal. `no_twin` = the plant today.

## Alarms on a healthy line

Read this table first. Lead time is only meaningful next to
the alarm rate that bought it — a trigger-happy rule always wins on lead and is always ignored
by the floor within a week.

| method | alarms per 8 h, healthy line | verdict |
|---|---|---|
| threshold | 141.6 | unusable — an alarm every three minutes is an alarm nobody reads |
| detection | 47.8 | unusable as an alarm; fine as a dashboard signal |
| loom | 0.0 | inside the published budget of 1 per five shifts |
